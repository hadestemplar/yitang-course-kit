# 契约层六件 —— 让数据包能被下游 Agent 直接吃掉

八节模板管「内容对不对」，契约层管「下游能不能直接用」。

一份数据包如果只有规则库，下游 Agent 拿到它必须先做三件苦力：猜这份输入够不够用、猜从哪一步开始、猜产出该长什么样。改一次就要重写一次适配。**契约层就是把这三件苦差事提前写死在包里**。

六件缺一件，下游就得重构。

---

## 第一件 · 输入分级（`§0.5`）

把「用户递过来的一段材料」分成三级，每一级写明：能产出什么、必须标什么、在哪里停机。

| 级别 | 输入形态 | 能产出 | 必须标注 | 停机点 |
|---|---|---|---|---|
| L0 | 只有叙述（背景 / 现状 / 想法），没有目标也没有数据 | 只能产出框架与待填项 | 全篇标「未提供」的字段 | 不得给出结论性判断 |
| L1 | 有明确目标，有部分数据 | 能产出方向判断 + 缺什么 | 缺数据处标「需补：X」 | 定量结论必须停 |
| L2 | 目标、数据、约束齐全 | 全流程产出 | 关键假设逐条列出 | 只在结论依赖外部未知时停 |

写法要求：三条各写一句，不要写成表格再让读者自己归纳（下游是 Agent，表格反而要被解析）。

## 第二件 · 分支表 + 停机问句（`§2.5`）

判完级别之后，走哪条分支、什么时候必须停下来问人。

- 分支表：≤3 条，每条写「如果输入是 X → 走 Y 分支 → 产出 Z」
- 停机问句：≤3 句，每句必须是**能直接发给用户的问题**，不是内部判断条件
  - 反例（不合格）：「若目标不明确则需澄清」——这是条件，不是问句
  - 正例：「这次要提升的是转化率还是客单价？两个方向的拆法完全不同。」

## 第三件 · 输出契约（`§3.5`）

给每一件交付物编号，写死字段。下游照编号取用，不需要理解课程。

一份业务类数据包的典型六件：

| 编号 | 交付物 | 必含字段 |
|---|---|---|
| D1 | 目标句 | 一句话目标 + 衡量口径 + 时间窗 |
| D2 | 结构树 | 至少两层，每个叶子节点可挂假设 |
| D3 | 假设池 | 假设 / 依据 / 影响面 / 可验证性 / 成本 / 优先级 |
| D4 | 取舍结论 | TopN + 砍掉哪些 + 砍的理由 |
| D5 | 验证计划 | 每条关键假设对应的方法 / 判据 / 时间盒 |
| D6 | 机制卡 | 谁在什么会议上、看什么指标、多久一次 |
| G | 缺口 | 缺什么、为什么缺、补了会怎样 |

规则：**契约层不得与课程原文混写**。课程说了什么属于规则库，字段长什么样属于契约层，两边的编号体系不要互相引用。

## 第四件 · 最小闭环优先级（`§4.0`）

规则库少则十几条、多则几十条，下游不可能全做。必须标出「只做这几条也算跑通」。

- **必做**：构成最小闭环的规则（通常 6–8 条），逐条标规则 ID
- **可省**：输入不足时可跳过，跳过后产出降级到什么程度要写清
- **仅参考**：只在特定行业/场景下用

## 第五件 · 术语映射（`§4.5`）

课程术语 ↔ 下游通用词 ↔ 用户口语。同一件事在三个语境里叫三个名字是常态，不映射就会被当成三件事。

| 课程术语 | 通用说法 | 用户可能怎么说 |
|---|---|---|
| （课程里的名字） | （行业内通行的名字） | （实际对话里出现的说法） |

## 第六件 · 黄金样例（`§6.5`）

一份**填满的**输出契约，让下游知道「合格长什么样」。要求：

- 覆盖 D1–D6 全部编号，不留空
- 素材自造，**明确标注「示例，不是本课原话」**
- 至少一处体现「输入不足以 L0 处理」的样子，让下游看到降级形态

---

## 自检（可机械核对）

1. `§0.5 / §2.5 / §3.5 / §4.0 / §4.5 / §6.5` 六个标题都在
2. 输入分级三行齐全，每行都有「停机点」
3. 停机问句以问号结尾，且不包含「若…则…」这类条件句
4. 输出契约每件都有字段表，编号连续
5. 最小闭环的规则 ID 都能在规则库里找到
6. 术语映射至少 3 行
7. 黄金样例覆盖全部 D 编号，且含「示例，不是本课原话」字样
8. 契约层与规则库没有互相引用编号

八条全过，才叫「下游不用重构」。
