# 抓课包（course-pack-capture）

## 这三层是什么

| 层 | 产出 | 目标用户 | 是否必做 | 本技能 |
|---|---|---|---|---|
| ① 抓课包 | **课程信息底稿**：可追溯、尽量完整 | 下游两条分支 | 所有课程都做 | ✅ 只做这层 |
| ② 数据包 | 操作手册型，能照着干 | Agent（我） | 按需 | ❌ 下游 Skill |
| ③ 清单体笔记 | 课程快照型，课程里有什么存什么 | 用户 | 按需 | ❌ 下游 Skill |

组合形态：①+②、①+③、①+②+③。**本技能不产出成品文档**——一旦开始"编排成十二节知识包"，就已经跨到 ② 了。

## 何时用 / 何时不用

用：用户给了课名/关键词/链接，要求"抓下来""取素材""准备数据包/笔记的原料"。

不用：
- 只要**数据包**或**清单体笔记**成品 → 走下游 Skill（底稿可复用，别重抓）。
- 只要某一门课的**单个字段**（上线日期、讲师）→ 直接 `whyai yitang course mine/info`，不必开抓取流程。

## 输入

最少一个：**课程名或关键词**（中文全称最准，如「一堂笔记法：清单式解题练习」）。
可选：关注的侧面（方法论/案例/图示）、预算轮次（默认 5 轮）。

## 输出位置

`C:\Users\hades\Documents\deepseek-harness\default-workspace\抓课包Skill\output\<课名>\`
- `00-底稿.md` —— 主产物（见 §底稿模板）
- `raw\` —— 每轮 Partner 原始输出，原样保存不改写
- `img\` —— 图示原件
- `prompt\` —— 每轮提示词

## 执行步骤

### 步骤 -1 · 开工自检（四连，不许跳过；≤30 秒）

```powershell
$env:Path = "$env:LOCALAPPDATA\WhyAI\bin;$env:Path"
whyai --version                     # 装了？没装走官方 install.mjs（Node ≥20）
whyai status                        # 必须 logged_in: true，看 gateway / environment
whyai billing access --json         # eligible / valid_until（过期或余额不足就停）
whyai --help                        # 子命令齐全？（本机 0.7.1 共 24 个顶层命令）
```

**自检没过就停下报环境问题，不要开工。**空结果必须解释成"环境/权限/工具"问题，**不许当成"课程库没收录"**——这是把假阴性写成事实的最短路径。

故障对照：

| 现象 | 原因 | 处置 |
|---|---|---|
| `CommandNotFoundException: whyai` | PATH 没前置 `%LOCALAPPDATA%\WhyAI\bin` | 前置后重试；新终端才生效 |
| `partners list` 为空 / 字段缺 | CLI 版本过旧 | `whyai upgrade` |
| 装过 npm 版又不生效 | 两套命令打架 | 卸一套重装 |
| `logged_in: false` / 401 | 未登录或凭据过期 | `whyai login --gateway https://ai.yitang.top` |
| 下载安装成功但 chat 报错 | **安装不需登录，chat/partners/课程库需登录且套餐有效** | 先 `billing access` |

### 步骤 0 · 拆关键词（四条扩词法）

用户给的词只当起点，先扩再检索；**至少要 3–4 个检索词**，否则漏课：

1. **同音 / 口误变体**——用户常用语音输入，同音字会被识别成别的词（如「课包」→「课班」）。**不要反问"是不是打错了"，直接按变体展开检索**，检索到再回头确认正字；正字一旦确认，全部产物统一用正字。
2. **近义词**：清单体/清单式/分点笔记、抓课包/取素材/课程信息。
3. **上位词**：笔记法 → 学习能力 / 个人必修 - 不断练能力。
4. **用户口述的课名、编号、场次一律当"待核实"**，逐一拿课程版AI 或 `course mine` 判真伪，不存在就直接说不存在。

### 步骤 1 · 定位课程（免费，优先做）

**这一层不消耗配额**（实测 `remaining_percent` 92 → 92 不变），能白拿的信息一律先拿：

```powershell
whyai yitang course mine --json                 # 我在学的全部课程（实测 69 门）
whyai yitang course search "<关键词>" --json     # 栏目包检索
whyai yitang describe course.info               # 查某能力的参数（发现层，免费）
whyai yitang course info <uniqId> --json        # 课程完整信息 + 我的学习状态
whyai yitang course sections <uniqId> --json    # 章节列表（可能为空）
```

`course mine` 每条含：`lessonId` / `uniqId` / `lessonTitle` / `subtitle` / `score` / `pitchword` / `answerExists` / `homeworkExists` / `peopleCount` / `textCount` / `studyStatus` / `selectTime` / `publishTime` / `navList`。

`course info` 补充：`name` / `subtitle` / `teacherName` / `tag` / `price` / `lessonStatus` / `lessonValid`。

> 价格、作业、Candy **不抓**（用户 2026-10-28 裁定：对下游无用；2026-11-06 复述「Candy 以后都不需要获取」）。`maxAnswerScore` / `homeworkExists` 这类字段忽略即可，也不要跑 `yitang homework`。Candy 只记「课程承诺发什么」这一句，**具名清单一律不追、不进缺口清单、不为此请用户开逐字稿**。

> **id 坑**：`course info` 与 `course sections` 只认 `uniqId`（形如 `8BwK673dae60bcc2`），传数字 `lessonId`（如 `1072`）会返回 `{"ok":false,"error":{"code":1000,"message":"您请求的页面不存在"}}`。

实测样例（一堂笔记法）：`lessonId=1072`、`uniqId=8BwK673dae60bcc2`、`publishTime=2026-06-11 14:25:18`、`textCount=7957404`、`teacherName=许楚Truman 一堂CEO`、`tag=个人必修 - 不断练能力 - 练记笔记`。**上线日期、讲师这类"问 AI 问不到"的字段，直连 API 一次就有。**

### 步骤 1.5 · 取官方大纲（免费，优先于 Partner 的 structure）

`course.sections` 对多数课返回 `items: []`——那是接口空，不是这门课没有章节结构。**官方大纲印在课程详情页的长图上**：

```powershell
whyai yitang call course.detail --param id=<uniqId> --json
```

- `data` 里有 `peopleCount / textCount / npsAvg`，`detail` 是一段 HTML，通常只挂一张 CDN 长图（`https://cdn.yitang.top/upload/...png`）。实测两种量级：**1382×4081**（五步法，约 2 屏）与 **1400×16251**（业务公式导入篇，9 屏）。
- **超过 3 屏一律切块读**：用 PIL 按 `1400×1800` 逐块 `crop` 存 `img\tile-<n>.png`，再逐块 `read_image`；一次性看全图必然漏字。逐字抄出章节标题与子节编号（`1.` 是大节，`1) 2) 3)` 是子节），转写落 `img\课程大纲-转写.md`，并写进底稿 `# 02 图示原件`；`# 01` 的骨架直接用这个层级。
- **大纲里的层级就是课程的层级，不许压平**：总分关系（例：「建立框架」下挂「五层理解」六节）以此为准；Partner 给的线性 `structure` 只作补充，冲突时以大纲图为 A 级。
- 详情页还能捞到口播里没有的事实：课程迭代年数、参与人数、「15 个常见错误」这类只在详情页出现的说法。与口播不一致时**两说并存并各自标注**，不要择一。
- `bundle.index` 实测返回 `YiTang returned an invalid response envelope`，别在这上面耗时间。
### 步骤 2 · Partner 雷达 + 选主抓

**主抓永远是课程版AI**——它背后是课程知识库；不指定 Partner 会落到"基础AI模型"（无课程库），课名课号必错。这是整个流程最常犯的错。

```powershell
whyai partners list --json            # 全景（实测 37 个，全 is_official:true）
whyai partners search "<关键词>" --json  # 至少 2 组关键词各搜一次
```

| 用途 | Partner | uuid | 说明 |
|---|---|---|---|
| 主抓（课程原文） | 课程版AI（`yitang-course-rag`） | `a0000000-0000-0000-0000-000000000001` | `conversation_access: unrestricted`，`knowledge_base_default_enabled: true`，**首选** |
| 补缺对账（判据/误区/边界） | 清单体笔记·刻意练习教练（`note-taking-practice`） | `e196861c-52b0-415c-a6a4-6676a0a489a4` | 字段写 `trial` 且 `conversation_window_end` 已过期，**实测仍可用** |

雷达结果处理：
- **命中 0 个**：记「本课无对口 Partner」，只用课程版AI，不要硬找；**命中 1 个**：直接跑这一轮对账，不需要凑到 2 个（实测业务公式导入篇只有「业务公式·拆解教练」1 个，照样跑出「五环节+18招与《关键假设业务拆解篇》同文」这条归属结论）。
- 按 `tcpr_type` 分组上报：**T 教学型 / C 咨询型 / P 实践型 / R 研究型**，并给一句话定位，让用户**点将**（相关 ≤2 个可自行全跑，超过就让用户选）。
- 点中一个 Partner 后先问两件事：① 这个课题该看哪些课包 ② **训练你时依据的是哪些课包**（后者能暴露它的知识来源，判断能不能当证据）。
- 开场必须说明目的（"我要把这个课题的课程信息完整抓出来"），否则它自由发挥。
- 追问一句"哪一步不该用你 / 你的边界在哪"。

要点：
- `partners get <slug>` 不认 slug，报 `invalid partner id` + `code: INVALID_REQUEST`；**必须传 uuid**。
- **换 Partner 做第二轮对账**，是这次唯一发现"AI 主动排伪证据"的配置——它能拒绝把别课的日期/评分规则挪用过来。
- 交叉验证（可选）：把"组合用法假设"写成编号步骤发给 ≥2 个 Partner 直言判断；一致才写进结论，不一致单列存疑。
- **独立性来自独立信源，不是独立角色**——多个 Partner 可能同源同模型，"交叉验证"可能只是重复。

### 步骤 3 · 分轮抓（一轮一个小目标）

```
r1 定骨（四问）：提前划的重点原话 / 为什么重要 / 边界与反例 / 主辅与删除测试
r2 补肉：课程元信息 + 大纲 + 全部模型 + 判断标准
r3 补肉：比喻口诀 + 作业原题 + Candy + 明确不在本课的内容
r4 定稿：把上面整成结构化全文
r5 终检：只报剩余缺口，不重写全文
r6 对账（换 Partner）：只做缺口对账
```

流程内按需插入 **r6+ 多轮深聊**（用于换 Partner 或补某个专家面）：同一会话用 `-c <uuid> --continue` 续聊，**默认 5 轮**。六个面覆盖齐才算聊透：

| 面 | 问什么 |
|---|---|
| 定位 | 你擅长什么 / 什么情况下不该找你 / 与其他伙伴的区别 |
| 推荐 | 这个课题该看哪些课包 / 只能留一门留哪门 |
| 理由依据 | 各解决哪个具体问题 / "值得"的标尺是什么 / 哪门主干哪门补充 |
| 主辅关系 | 并列还是递进 / 不学哪门就学不了后面 / 只能学一半砍谁 |
| 边界 | 何时无效甚至有害 / 最容易被误用成什么样 / 失败的反面案例 |
| 分工 | 与另一个 Partner 怎么分工 / 哪一步该换人 |

调用形态（提示词写文件，用 `@file` 传入，避免命令行转义灾难）：

```powershell
whyai chat --partner a0000000-0000-0000-0000-000000000001 `
  --title "〈课名〉·底稿r1" "@C:\...\prompt\r1.md"
whyai chat -c <会话uuid> --continue "@C:\...\prompt\r2.md"
```

> `--knowledge-base` 对课程版AI 可省（`partners get` 实测 `knowledge_base_default_enabled: true`，默认就开）。加了不报错，属冗余。

铁律（都是实测踩出来的）：
1. **一轮只问 1–2 个缺口**。一次问六件事，Partner 只会挑好答的回答。（同学版 v3 主张"配额按字节计费，一次问全"；本机实测是**按次 2 点**，分轮更划算，所以保留分轮。）
2. **不要给它结构性微指令**。要"只输出三块""加一张原话库表格"这类格式要求，它会静默改写成"补全/终检定稿"——连续两次都没照做。要格式就自己重排。
3. 提示词里写死：**不要反问我、不分轮、直接 Markdown**。
4. **红线：不杜撰**。查不到就写"查不到 / 未收录"，绝不推测填充。
5. **红线：不写落地建议**。底稿是纯课程素材，不含"你可以拿它做 X"。
6. 抓到的正文一律存 `raw\rN.md`，**不改写**；改写只发生在 ②③ 层。

### 步骤 4 · 图示一律看原件

课程的结构图/地图/小抄，**文字 OCR 不可靠**：同一张图两套 OCR 会给出互相冲突的列归属，且"读到一致"不等于"读对"——那只是同一个坐标系重复失效。

做法：
1. 拿到原图文件（用户提供 / 附件 / 课程页），存 `img\`。
2. 用 PIL 按行切带、放大 2–4 倍后逐块读（不要整图缩着看）。
3. 把读出的结构**转写成 Markdown 表格**进底稿，并在表下注明"来源：原图文件名 + 读取方式"。

实测教训：训练地图 15 个标签、5 组练习要点、6 个目标，全部靠原图 8 次放大才读准；此前问 AI 得到的是"16 条标签、3 条不可定"——错 3 处。

### 步骤 5 · 缺口三道闸（不许跳过第二道）

1. **换问法再试一次**（不同切入点、不同关键词），仍无结果 → 进入下一道。
2. **向用户提问**。用户可以打开课程**逐字稿**，很多"查不到"是检索不到而非不存在。
   - 一问一次性列清：缺口清单 + 每条我试过什么问法 + 我需要的是什么级别的东西。
   - 值得问：结构化图示、章节骨架、术语正字、判定标准、上线/版本信息。
   - 不值得问、直接放掉：作业评分细则、Candy 兑换、版本号（用户明确说过不重要）。
3. **记"查不到"**，并要求同时记下**试过的问法与失败原因**（图注非正文 / 标签行被压成流水 / 操作法挂在直播课）。只写"查不到"没有价值，"为什么会查不到"才有。

### 步骤 5.5 · 数量对账（免费；漏掉一整个阶段的根因就在这里）

元信息、详情页、官方大纲只要**承诺了数量**，就必须在落底稿前逐个数一遍、逐条打勾：

- 承诺来源：详情页文案（例：「复盘营 **4 个不同阶段**的业务公式进化」）、官方大纲的节数与节内条目数（例：「五步法修炼 **6 个段位**」「关键假设 **18 招**」）、元信息的 `textCount` 之外的结构性描述。
- 动作：把承诺数量与实际抓到的条目并排列出来（`承诺 4 / 实际 3`），逐个写出名字与出处行号。
- 对不上时：缺的那一项写进 `## 4 缺口清单`，写明「第 k 个：抓取资料里没有」，并**先走步骤 5 的换问法**再记账。**不许**把后一阶段的成果挪来顶替，也不许因为数不齐就把编号抹平（把「阶段四」写成「长期结果」就是这类事故）。
- 编号归属：Partner 重构过的「阶段一/二/三」**不是**课程原编号，必须注明「编号来自 Partner 转述，课程原文只出现第一/第二阶段」这类口径；课程原文没有编号时，跟我方编号要标「编者编号」。
### 步骤 5.6 · 收尾段必录（大纲未列也要收）

官方大纲通常只有主体章节，**开场、结课（收尾）、作业与 Candy 说明三段往往不在大纲里**。这三段不录，下游笔记与数据包都会缺一块，且没人报错——2026-10-30 业务公式导入篇就因此丢了整段结课（白盒/黑盒、因果信念、四句价值排序、修炼顺序），当时被删除测试判成「价值观收口」只留一行。

- 检查项：`grep -n "结课|收尾|好啦|作业|Candy" raw\*.md`，把命中的原话逐条落进底稿。
- 底稿动作：在 `# 01 内容本体` 末尾单独设一节「结课/收尾」，标 `〔大纲未列·正文存在〕`，原话照抄，不压缩成一句。
- **删除测试不作用于收尾段**：它本来就不是操作层，「删掉不影响操作性」不能作为删除理由。
- 缺口三联：抓不到就进 `# 04 缺口清单`，写明「结课未取到」；不许用一句「价值观收口」敷衍过去。
### 步骤 6 · 落底稿

按下面的模板写进 `output\<课名>\00-底稿.md`；用 `[System.IO.File]::WriteAllText(path, text, [System.Text.UTF8Encoding]::new($false))`，**不要用 `Out-File`**（会写 BOM）。

## 底稿模板（五节；内容本体必须占全文字数 80% 以上）

> **底稿只负责"拿到"，不负责"排好"。**不许摘要、不许挑重点、不许合并同类项、不许"提炼成表格"。
> 2026-10-28 实际翻车：底稿写成了元信息 + 几张引文，把"什么是清单体笔记 / 为什么要学"整块丢掉，被用户判「信息丢得厉害，还不如上一版」。
> 判据很简单：**底稿能自己回答"它是什么 / 为什么要学 / 具体怎么做"三个问题**，答不上来就是废稿。

```markdown
# 〈课名〉·课程信息底稿

## 0 元信息
- 课名 / 副标题 / 讲师 / 标签 / 课程 uniqId 与 lessonId
- **元信息与「体系位置」只留在这一节**：系列位次、前置/延展课程、讲师履历、版本与价格不写进 `# 01 内容本体`；下游清单体笔记的正文不设「本课在体系中的位置」小节（用户 2026-10-29 裁定）
- 上线时间（publishTime）/ 文字量（textCount）/ 是否在学
- 课程结构：`course sections` 返回几章（返回空就写明"无章节"）
```

## 已知坑（全部实测）

1. `partners get <slug>` 只认 uuid。
2. `ConvertFrom-Json` 前必须 `Out-String`，否则对象被拆行。
3. `2>&1` 会把 stderr 包成 PowerShell 错误记录混进正文；截正文从首个 `^#\s` 行起，并过滤 `^\[tool\] ` 行。
4. `Select-Object -First N` 会掐断上游管道，导致假 `exit code 1`。
5. 写 `.md` 一律 `WriteAllText` + `UTF8Encoding($false)`；`Out-File -Encoding UTF8` 会写 BOM。
6. `whyai notes list --json` 返回的是**单个 note 对象**而非列表；核对笔记请只打印 `title/created_at`，整段 `ConvertTo-Json` 曾把 1.5 万字笔记全文灌进上下文。
7. `course info/sections` 要 `uniqId`，`course mine` 的 `lessonId` 是数字、`uniqId` 是字符串，别混。
8. 读文本一律 `-Encoding UTF8`：PS 5.1 默认 GBK，中文会乱码且会吞掉紧跟中文的 ASCII 数字。
9. 输出常是长段落无换行：先 `grep -n "^#"` 定位，再按区间读。
10. 首行 `Created conversation <uuid>` 必须记下，续聊全靠它。
11. 【待核实，同学版 v3 报告】后台 chat 飞行期间，其它 `whyai` 命令会报 `CLI quota is exhausted`——那是预冻结假象，不是真耗尽。本机未复现；遇到时先等 chat 结束再查。
12. 图形类结论（刻度位置、口诀归属、颜色分区）Partner 只能给"不可判定"，**必须向用户要原图截图**；拿到原件后按色值定位即可判定——本课及格线就是扫描红色竖线 x=1298、再与灰分隔线 x=524/911/1686/2073（等距 387）比对，确认它正好落在 L3/L4 分界上。

13. `chat --title` 过长直接失败：`whyai: 标题过长 / code: BAD_REQUEST`（**不扣配额**）；标题控制在 12 字内，别带括号与说明。
14. `partners search --json` 输出是**裸 JSON 数组**，不是 `{data:…}`；按 `{` 起点解析会得到 0 条，要从 `[` 截到最后一个 `]`。
15. 在 `run_code`/Node 里 spawn `whyai.cmd` 必须显式传 `env`（沙箱 `process.env` 为空），否则报 `not logged in`——至少给 `APPDATA / LOCALAPPDATA / USERPROFILE / SystemRoot / TEMP / TMP / PATH`。

- **坑 13 · `course.sections` 返回空 ≠ 课程没有结构。** 多数课的 section-list 就是空数组（笔记法课、五步法课都如此）。判据不是接口有没有返回，而是官方大纲图里有没有章节；先跑步骤 1.5 再谈骨架。
## 验收（缺一条即为没做完）

1. 底稿**五节**齐全（0 元信息 / 1 内容本体 / 2 图示 / 3 术语 / 4 缺口），缺的节写了为什么缺；内容本体占全文 ≥80%。
2. 每一条主张都能指回"哪门课/哪一节"；没有出处的主张一律标"编者判断"或删除。
3. 图示有原件路径 + 转写表，且转写不是 OCR 转述。
4. 缺口清单里每条都带"试过的问法"。
5. 配额从起始值到结束值有记录，且与轮次数对得上。
6. 下游若只做 ② 或 ③，**不需要再调用一次 Partner**。
7. 命令里出现过 `--partner a0000000-0000-0000-0000-000000000001`（不是裸 `whyai chat`）。
8. 主抓 Partner 之外，至少跑过 2 组 `partners search` 并给出 `tcpr_type` 分组的点将清单。
9. 全文**没有任何落地建议、公司结合建议、"你可以用它做 X"**。
